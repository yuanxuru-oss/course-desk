# 技术说明

给想读代码或改代码的人。产品层面的介绍在根目录 [README](../README.md)。

## 形状

纯前端 PWA,没有后端(除了一个可选的通知转发服务)。

```
src/
  lib/          核心逻辑(不碰 DOM,基本都能单测)
    time.ts       周次换算、节次时间、课程冲突
    schedule.ts   作息表生成 / 文本互转
    import.ts     Excel / CSV / 二维表解析
    pdfTable.ts   PDF 文字坐标 → 二维表
    pdfGrid.ts    PDF 表格线 → 格子 → 课程(最硬的一块)
    nl.ts         自然语言 → 课程 / 作业 / 行程
    quickCapture.ts  全局粘贴的阈值与判重
    event.ts      行程 → 节次行、并排布局
    reminderEngine.ts  提醒计划生成与投递
    knowledge.ts  BM25 检索
    ai.ts         OpenAI 兼容 / Anthropic 客户端
  components/   界面
  db.ts         Dexie(IndexedDB)表结构
  store.ts      设置与 Toast
server/         可选的推送转发服务(零依赖 Node)
scripts/        单测、端到端冒烟、打包、图标生成
```

## 数据

全在 IndexedDB 里(库名 `course-desk`),没有账号,没有上传。
图片以 blob 存,备份时转成 base64 放进 JSON。

## 三件比较难的事

### 1. PDF 课表还原

教务系统导出的 PDF 分两类:

- **画了表格线的**:先取 PDF 的路径操作拿到所有横线竖线,聚类出列;每一列单独取横线(合并单元格中间没画线),得到真实格子;再把格子里的文字按阅读顺序拼回去 —— 这样"逐字折行"和"老师名字被拆成两半"都能复原。
- **没画线的**:退回到"按 y 聚行 + 按 x 间隙切格 + 用表头定列"的启发式。

两条路互斥,按优先级尝试;都失败再退回纯文本按行解析。
同名课被按周次拆成多段的,合并成一条(周次取并集,换老师记进备注)。

### 2. 判重

每门课有一个「内容签名」:课程名 + 星期 + 节次 + 周数 + 周次 + 教师 + 教室。
导入时先比签名,已有的跳过;id 由签名哈希得到,所以同一份课表导两次不会变成两份。
启动时还会把历史遗留的重复 / 分段合并一次。

### 3. 提醒

浏览器页面关掉后定时器就停了,所以"关掉还能提醒"只能靠外部:

- 系统通知:页面开着时才准
- 微信(Server 酱):前端直接请求,或走 `server/` 代理
- Web Push:由 `server/` 保存提醒计划并定时下发

三条通道都是可选的,不配也不影响主功能。

## 开发

```bash
npm install
npm run dev        # http://localhost:5173
npm run typecheck  # tsc --noEmit
npm test           # 单测(解析器 / 导入 / PDF 还原 / 检索)
npm run build      # 生产构建 → dist/
```

端到端冒烟需要本机 Chrome:

```bash
npm run build
node scripts/smoke-e2e.mjs <站点地址> <测试PDF路径>
```

## 部署

构建产物是纯静态文件,任何静态托管都能放(`dist/` 直接丢上去)。
项目本身用 GitHub Pages:`gh-pages` 分支放构建产物,`main` 放源码。

> 注意:`base` 配的是 `./`,所以放在任意子路径(例如 `/repo-name/`)都能正常跑,Service Worker 的 scope 也会跟着走。

## 已知限制

- 没有账号体系,多设备同步靠导出 / 导入 JSON
- 系统通知在页面关闭后不生效(浏览器限制)
- 扫描件 PDF(没有文字层)需要改用截图 OCR
